# **セキュリティホワイトペーパー**

_最終更新日: {{YYYY-MM-DD}}_

本書は、NexLetter がどのようにデータを処理・保護するかを透明性をもって説明するためのホワイトペーパーです。

---

## 1. Overview（概要）

NexLetter は、Slack や GitHub などのコラボレーションツールからチームの活動データを収集・要約し、自動ニュースレターや分析レポートを生成する AI プラットフォームです。

本ホワイトペーパーでは、NexLetter がユーザーデータをどのように処理し、保護しているかを現実的かつ透明性のあるレベルで説明します。

---

## 2. Security Principles（セキュリティ原則）

NexLetter は以下の原則に基づいて設計されています：

1. **最小権限アクセス（Least Privilege Access）**

   必要最小限の OAuth 権限のみを要求し、それ以外のデータにはアクセスしません。

2. **通信経路の暗号化（HTTPS/TLS）**

   全ての通信は TLS を用いて暗号化されています。

3. **データ最小収集（Minimal Collection）**

   要約や分析に必要な以上の生データは保存しません。

4. **AI 学習への利用禁止**

   ユーザーデータは AI モデルの学習や再学習には一切使用しません。

5. **透明性のあるデータ処理**

   収集・保存するデータを明確に公開します。

---

## 3. Authentication & Authorization（認証と認可）

### ✔ OAuth ベースのログイン

- GitHub、Google、Slack、Apple の OAuth に対応  
- NexLetter はパスワードを保存しません

### ✔ アクセス制御ポリシー

- Slack の DM や非公開メッセージ本文は保存しません  
- GitHub リポジトリはインストールされた範囲内のみアクセス  
- Workspace のユーザー/権限は管理者が管理します  

---

## 4. Data Handling Policy（データ処理ポリシー）

### 4.1 収集されるデータの種類

以下の区分でデータを処理しています：

---

### **① 要約・レポート生成のための一時データ（処理後は破棄または最小保持）**

- Slack メッセージ本文（要約目的）
- GitHub PR/Issue のタイトル・説明  
- コミットメッセージ  

> ⚠️ 生データを長期保存することはありません。  
> 要約に使用されたデータは保持せず、または可能な限り最小化します。

---

### **② ダッシュボード・分析のための最小限のメタデータ（必要不可欠な情報のみ保存）**

保存されるメタデータ：

- イベント/メッセージのタイムスタンプ  
- メッセージ数・コミット数などのカウント情報  
- チャンネル ID / リポジトリ ID  
- ユーザー ID またはハッシュ化識別子  
- Slack メッセージ総数、PR 数、コミット数などの統計  
- ニュースレター送信結果（成功/失敗）  
- チーム/ユーザーの活動推移  

> これは分析提供のために必要な最小データであり、  
> 原文データは含まれません。

---

### **③ 保存しないデータ**

- Slack DM や個人メッセージ本文  
- GitHub ソースコード  
- 添付ファイル  
- 非公開リポジトリ内の原文データ（許可範囲外）  
- 個人のセンシティブ情報  

---

## 5. Data Storage & Encryption（データ保存と暗号化）

- 安全なクラウド環境にデータ保存  
- 保存時はクラウド標準の AES-256 による暗号化  
- 通信時は HTTPS(TLS 1.2+)  
- OAuth トークンは安全な Vault に保存  

> NexLetter は現時点で BYOK や完全なエンドツーエンド暗号化を提供していません。  
> 必要に応じて将来のロードマップで検討される可能性があります。

---

## 6. AI Processing & Privacy（AI 処理とプライバシー）

### ✔ AI 学習禁止ポリシー  
Slack メッセージ、PR、コミット内容などは **AI モデルの学習に使用しません**。

### ✔ セッション単位処理  
要約処理が完了したデータはセッション終了時に破棄されます。

### ✔ AI トーン＆スタイル設定（今後の機能）  
チームの文体、禁止ワード、ブランドガイドに基づいた  
AI 出力調整機能を提供予定です。

---

## 7. Access Control（アクセス制御）

- Workspace 管理者権限  
- Integration の追加/削除は管理者のみ可能  
- ユーザー招待/削除機能  
- メンバーは所属 Workspace のデータのみアクセス可能  

---

## 8. Logging & Monitoring（ログと監視）

- システムログ・エラーログ収集  
- ログにはメッセージ本文などは含めません  
- 不正 API リクエストは自動的にブロック  

---

## 9. Data Deletion & Retention（データ削除と保持）

### ✔ Workspace/アカウント削除時  
→ 関連データは復元不可能な形で削除されます。

### ✔ 分析用メタデータ  
→ 顧客の依頼により手動削除可能。

---

## 10. Roadmap（今後の予定）

### ⭐ 短期（2026）
- Workspace レベルのデータ保持期間設定  
- Slack/GitHub イベントフィルタ強化  
- 管理者承認フロー（2 段階承認）  
- **AI トーン＆スタイルプロファイル設定**  
- 分析ダッシュボードの拡張

> 現時点で計画に含まれておらず、必要に応じて長期的に検討されます。
