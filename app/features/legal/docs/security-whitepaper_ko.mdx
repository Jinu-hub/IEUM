# **보안백서(Security Whitepaper)**

_최종 업데이트: {{security_last_updated}}_

본 문서는 NexLetter의 보안·데이터 처리 정책을 고객에게 투명하게 안내하기 위한 화이트페이퍼입니다.

---

## 1. Overview

NexLetter는 Slack, GitHub 등 협업 도구에서 팀 활동 데이터를 수집·요약하여

자동 뉴스레터 및 분석 리포트를 생성하는 AI 기반 플랫폼입니다.

본 화이트페이퍼는 NexLetter가 사용자 데이터를 어떤 방식으로 처리하고 보호하는지

현실적이고 투명한 수준에서 설명합니다.

---

## 2. Security Principles

NexLetter는 다음의 핵심 원칙을 기반으로 설계됩니다:

1. **최소 권한 접근 (Least Privilege Access)**
    
    필요한 OAuth 권한 범위만 요청하며, 이외 데이터는 접근하지 않습니다.
    
2. **전송 구간 암호화 (HTTPS/TLS)**
    
    모든 네트워크 요청은 TLS 암호화를 사용합니다.
    
3. **데이터 최소 수집 (Minimal Collection)**
    
    요약 및 분석에 필요한 범위 이상의 원문 데이터는 저장하지 않습니다.
    
4. **고객 데이터는 AI 학습에 사용하지 않음**
    
    고객 데이터는 LLM 학습이나 재학습에 활용되지 않습니다.
    
5. **투명한 데이터 처리**
    
    어떤 데이터를 수집하고 저장하는지 고객이 이해할 수 있도록 명확히 공개합니다.
    

---

## 3. Authentication & Authorization

### ✔ OAuth 기반 로그인

- GitHub, Google, Slack, Apple OAuth 인증 지원
- 자체 비밀번호를 저장하지 않음

### ✔ 접근 권한 정책

- Slack DM, 비공개 메시지 본문은 저장하지 않음
- GitHub Repo는 고객이 설치한 범위 내에서만 접근
- 관리자는 Workspace 사용자·권한을 직접 관리

---

## 4. Data Handling Policy

### 4.1 수집되는 데이터 유형

NexLetter가 수집하는 데이터는 다음과 같이 구분됩니다.

### **① 요약 및 리포트 생성을 위한 임시 데이터 (일시 처리 후 폐기 또는 최소 보관)**

- Slack 메시지 본문 (요약 목적)
- GitHub PR/Issue 제목 및 설명
- 커밋 메시지

> ⚠️ 원문 데이터를 장기적으로 저장하지 않습니다.
> 
> 
> 요약 처리에 사용된 데이터는 저장하지 않거나 가능한 한 최소화된 형태로만 유지합니다.
> 

---

### **② 대시보드·Analytics용 최소 메타데이터 (필수 정보만 저장)**

아래 정보는 서비스 기능 제공을 위해 저장됩니다:

- 메시지/이벤트 발생 시각
- 메시지/커밋의 개수(카운트 정보)
- 채널 ID / 저장소 ID
- 사용자 ID 또는 해시된 사용자 식별자
- Slack 메시지 수, PR 수, 커밋 수 등 누적 통계
- 뉴스레터 발송 성공/실패 기록
- 팀/사용자 활동량 변화량

> 이는 대시보드 통계 제공을 위한 최소한의 메타데이터이며,
> 
> 
> 원문 내용을 포함하지 않습니다.
> 

---

### **③ 저장하지 않는 데이터**

- Slack DM 또는 개인 메시지 본문
- GitHub 코드 파일(소스 코드)
- 파일 첨부물
- 비공개 저장소의 원문 데이터 (허용된 범위 외)
- 사용자의 개인 민감정보

---

## 5. Data Storage & Encryption

- 모든 데이터는 안정적인 클라우드 환경에 저장됩니다.
- 저장 시 클라우드 기본 암호화(AES-256) 적용
- 전송 시 HTTPS(TLS 1.2+) 적용
- OAuth 토큰 등 민감 정보는 안전한 보관소(Vault 등)에 저장

> NexLetter는 현재 고객 제공 키(BYOK) 또는 전 구간 E2EE는 지원하지 않습니다.
> 
> 
> 필요 시 향후 로드맵에서 고려될 수 있습니다.
> 

---

## 6. AI Processing & Privacy

### ✔ AI 학습 금지 정책

NexLetter는 고객 메시지·PR·커밋 내용 등 어떠한 데이터도

AI 모델 학습에 사용하지 않습니다.

### ✔ 세션 단위 처리

요약·분석 요청이 끝나면 해당 데이터는 세션 내에서 폐기됩니다.

### ✔ AI 톤 & 스타일 설정 (Upcoming Feature)

팀별 톤/스타일/금칙어/브랜드 가이드 기반으로

AI 출력 형태를 맞추는 기능을 향후 제공 예정입니다.

## 7. Access Control

- Workspace 단위 Admin 권한
- Integration 추가/삭제는 Admin만 가능
- 사용자 초대/삭제 관리 제공
- 멤버는 본인이 속한 Workspace 데이터만 접근 가능

---

## 8. Logging & Monitoring

- 시스템 로그 및 오류 로그 수집
- 로그에는 메시지 본문 등 민감 데이터 저장 없음
- 비정상적 API 요청은 자동 차단

---

## 9. Data Deletion & Retention

→ 관련 데이터 자동 삭제 (복구 불가)

### ✔ 대시보드용 메타데이터

→  고객 요청 시 수동 삭제

## 10. Roadmap (Upcoming Features)

향후 NexLetter가 제공할 예정 또는 검토 중인 보안/데이터 관련 기능은 다음과 같습니다.

> ⚠️ BYOK, HIPAA, SIEM 스트리밍 등 엔터프라이즈 기능은 현재 계획 범위에 포함되지 않으며
