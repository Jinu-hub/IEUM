## 2026-10-20

### core_json v2: evidence 정규화 (`daily-core-v2`)

`works/out/flue-runs/20261020/3/4.core.json` 실측: 84.6K자 중 evidence가 78%(66K). 고유 evidence는 84개인데 183번 복사되고, member_activity가 작성자별 필터로 하루치 전체를 한 번 더 들고 있는 게 원인. 실제 내용(title+summary)은 4%뿐.

- 아이템은 `evidence_refs`(source_ref)만 들고, evidence 실물은 문서 뒤쪽 최상위 `evidence` 맵에 ref당 1벌(시간순). member_activity도 같은 맵 공유.
- URL은 evidence에서 제거. 소스당 1줄인 `sources`(Slack `channel_id`는 정규화 `meta.channel_id`에서, GitHub `base_url`은 URL prefix에서)를 뒤쪽에 두고, 링크는 읽는 쪽(`daily-report.ts`의 `evidenceUrl`)이 조립. Slack은 `thread_ref`(답글일 때만, 부모 ts 원문)로 스레드 쿼리까지 복원.
- 패턴이 안 맞는 경우의 탈출구: 링크 베이스를 못 구한 소스의 항목은 `url`을 그대로 남기고 `thread_ref`는 뺌(URL에 이미 있음). 읽는 쪽은 `url`이 있으면 그걸 우선.
- 생략: 빈 `tags`/`entities`/`classifications`/`confidence`, null인 `status`/`author`/`excerpt`, 빈 `payload` 키 자체. enricher가 채우면 그때 키가 생김.
- 보조 테이블은 안 만듦(사용자 검토): 원본 URL은 이미 `daily_core_source_data.normalized_json`에 있고, `daily_core_items.evidence_json`에 넣으면 아이템별 중복이 재현됨. 에이전트 토큰 부담은 evidence 맵을 에이전트 입력에 안 넣는 것으로 해결(Writer 입력은 이미 그렇게 됨).
- v1 호환: 저장된 v1 generation의 리포트가 깨지지 않게 `itemEvidence`가 인라인 evidence(구형)도 받음. 앱 계약(`pipeline-result.ts`)도 v2로 맞춤.
- 검증: 실제 run 데이터(20261020/3)를 v2로 변환하면 84.6K → 41.4K(-51%), 변환 전후 렌더한 markdown/HTML이 바이트 단위로 동일. `daily-core.check.ts`·`daily-report.check.ts`·flue/앱 tsc 통과 (앱 tsc의 `works/out` 스냅샷 오류는 기존 것).
- 보강(같은 날 후속): URL 생략 판정을 소스 단위 → 항목 단위로. 조립 로직을 `deriveEvidenceUrl`(daily-core)로 모으고, 빌드 시 재조립 결과와 원본을 호스트만 무시하고 비교해 다르면 URL 유지. 알려진 소스에 모르는 형태(예: GitHub release)가 섞여도 링크가 조용히 사라지지 않음. 체크에 혼합 형태 케이스 추가.
